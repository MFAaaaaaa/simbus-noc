# simbus_noc

`simbus_noc` is a standalone C++17 NoC abstraction module extracted from the bus/network model style used by `nullrvsim/src/bus`.

It provides:

- `BusInterfaceV2`: port/channel send-recv interface
- route-table generators: single ring, double ring, 2D XY mesh
- `SymmetricMultiChannelBus`: cycle-driven multi-channel NoC model
- bounded router buffer + watermark-based congestion/backpressure
- standalone tests with CTest

## Build and test

```bash
cmake -S . -B build
cmake --build build -j
ctest --test-dir build --output-on-failure
```

## Minimal usage

```cpp
#include "simbus/symmulcha.h"

using namespace simbus;

int main() {
    std::vector<BusNodeT> nodes{0, 1, 2, 3};
    BusRouteTable route;
    genroute_double_ring(nodes, route);

    NocConfig cfg;
    cfg.link_width_byte = 8;
    cfg.route_latency = 2;
    cfg.congestion.enabled = true;
    cfg.congestion.node_buffer_limit = 16;
    cfg.congestion.high_watermark = 12;
    cfg.congestion.low_watermark = 4;

    SymmetricMultiChannelBus bus({0, 1, 2, 3}, nodes, {4}, route, cfg);

    std::vector<uint8_t> payload{1, 2, 3, 4, 5};
    bus.send(0, 2, 0, payload);

    while (!bus.can_recv(2, 0)) {
        bus.apply_next_tick();
    }

    std::vector<uint8_t> recv;
    bus.recv(2, 0, recv);
}
```

## Congestion-control model

The first congestion-control mechanism is intentionally conservative:

1. Every router has a bounded packet buffer counter.
2. Packets admitted to a forwarding router pipeline consume one buffer slot.
3. Destination receive/reassembly buffers remain unbounded, matching the original simulator simplification and avoiding deadlock on multi-packet messages.
4. If admitting a forwarding packet would exceed the limit, the node does not detach the packet from the upstream edge output or local send buffer.
5. This creates backpressure naturally: upstream edge output remains occupied, edge input cannot move forward, and earlier routers eventually block.
6. High/low watermarks are used to avoid oscillating `can_send()` near the limit.

## Current test coverage

The test executable is split into focused files:

- `test_routetable.cpp`: ring, double-ring, 2D mesh XY routing and invalid node input
- `test_basic_transfer.cpp`: same-node transfer, cross-node transfer, multi-channel independence, zero-length messages, and padding removal
- `test_congestion.cpp`: backpressure/recovery, latency increase under congestion, throughput reduction under congestion, and source-node `can_send()` gating
- `test_stress.cpp`: randomized no-loss checks with normal and small router buffers

## Benchmarking congestion behavior

The v3 package also builds a small benchmark executable:

```bash
cmake -S . -B build
cmake --build build -j
./build/noc_benchmark --topology mesh --nodes 16 --mesh-x 4 --mesh-y 4 \
  --pattern hotspot --offered-load 0.8 --ticks 10000 \
  --buffer-limit 8 --high-watermark 6 --low-watermark 2
```

The benchmark prints one CSV row with metrics such as injected messages, delivered messages, average packet latency, throughput, blocked cycles, congested cycles, and edge busy cycles.

Useful comparisons:

```bash
# Backpressure / bounded buffering enabled
./build/noc_benchmark --pattern hotspot --offered-load 0.8 --congestion 1 \
  --buffer-limit 8 --high-watermark 6 --low-watermark 2

# Unbounded buffering / no congestion control
./build/noc_benchmark --pattern hotspot --offered-load 0.8 --congestion 0 \
  --buffer-limit 8 --high-watermark 6 --low-watermark 2
```

Run a small sweep and save it as CSV:

```bash
./scripts/run_sweep.sh ./build/noc_benchmark noc_sweep.csv
```

The benchmark supports two traffic patterns:

- `uniform`: each source picks a random destination other than itself.
- `hotspot`: most non-hotspot nodes send to `--hotspot-node` with probability `--hotspot-prob`.

It supports three topologies:

- `mesh`: generated by `genroute_mesh2d_xy`.
- `ring`: generated by `genroute_single_ring`.
- `double_ring`: generated by `genroute_double_ring`.

## v4: plotting and drain-status fields

The benchmark CSV now distinguishes between delivered and still-in-flight traffic:

- `undelivered_messages`: `injected_messages - delivered_messages` after the drain phase.
- `in_flight_messages`: current message-level in-flight count. In this benchmark it is the same as `undelivered_messages`.
- `drain_timeout`: `1` if the benchmark exhausted `--drain-ticks` while messages were still in flight; otherwise `0`.

This avoids interpreting a finite drain timeout as packet loss.

Run the sweep:

```bash
./scripts/run_sweep.sh ./build/noc_benchmark noc_sweep.csv
# or, if execution permission was not preserved by your archive tool:
bash ./scripts/run_sweep.sh ./build/noc_benchmark noc_sweep.csv
```

Generate plots:

```bash
./scripts/plot_sweep.py noc_sweep.csv --out-dir plots
# or:
python3 ./scripts/plot_sweep.py noc_sweep.csv --out-dir plots
```

The plotting script generates one PNG per metric and traffic pattern, including:

- `avg_packet_latency`
- `throughput_bytes_per_tick`
- `blocked_cycles`
- `congested_cycles`
- `delivery_ratio`
- `source_blocked_messages`
- `undelivered_messages`

If `matplotlib` is not installed, install it with:

```bash
python3 -m pip install matplotlib
```
